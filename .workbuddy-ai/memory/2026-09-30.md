## LightGateway：改造「读取」流程（自动重试 + 单一成功弹窗）

- 需求：点击「读取」失败时不弹错误窗，改为自动重试；仅最终读取成功时弹一次窗，提示进入老化架选择。
- 改动文件：`ViewModel/MainViewModel.cs`、`CLAUDE.md`（新增 "Read Flow (读取：自动重试 + 单一成功弹窗)" 章节）。
- 实现要点：
  - 新增 `ReadMaxAttempts = 3` / `ReadRetryDelayMs = 300` / `IsReading`，以及
    `TryReadConfigWithRetryAsync()` —— 包在 `DoReadConfig()` 外层，**不修改 `DoReadConfig` 本身**。
  - `case "读取"` 重写：失败只写 `ReadStatusMessage`（不弹窗）；成功弹唯一一次窗
    「读取配置成功，请进入老化架选择。」，并保留与 `WroteSnapshot` 的一致性比对结论。
  - 读取改为 `await Task.Run(DoReadConfig)` 后台执行，因此新增 `IsReading`/`IsWriting` 互斥
    （两个 case 入口都 `if (IsReading || IsWriting) return;`）—— 这是新引入的必要保护，
    因为 `SerialModel.Send` 有锁而 `ReadOneFrameData` 没有，并发会互相污染收发。
  - 有意未改动：`写入` 的回读、`读取并匹配老化架` 仍走原始 `DoReadConfig()`，不参与重试。
- 验证：`dotnet build LightGateway.slnx` → 0 错误；190 个警告全部为既有 nullable/Fody 警告，
  已用行号核对确认新增代码区间（175-236 / 400-425 / 465-505）零警告。
- 待确认（已向用户说明）：重试耗尽后是否也要弹一个兜底错误窗 —— 当前按需求字面实现为**完全不弹**。
