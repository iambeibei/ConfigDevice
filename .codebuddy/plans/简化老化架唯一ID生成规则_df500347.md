## 用户需求
老化架按老化架号自动生成「简化版」唯一 ID，不再生成重复的六段式格式。老化架号 `10` 应生成 `10`，而不是 `10:10:10:10:10:10`。

## 产品概述
LightGateway（WPF 桌面端）中的老化架模板，其「Mesh ID」此前由老化架号派生为 MAC 风格的六段字符串（如 `01:01:01:01:01:01`）。现要求生成逻辑直接使用原始老化架号本身作为唯一标识，格式简洁统一。

## 核心功能
- 老化架号 → 唯一 ID 的生成规则改为原样输出：输入 `10` 得到 `10`，输入 `1` 得到 `1`（不再补零、不再重复拼接）。
- 仅在 Mesh ID 为空时自动生成；已由用户填写或已保存的历史值保持不变，不做迁移与覆盖。
- 同步文档注释，使注释描述与新格式一致（不再描述「每段两位、共六段」）。


## 技术栈
- 现有项目：WPF + C#（.NET），MVVM（Model / ViewModel / View 分层），Fody `PropertyChanged` 注入。
- 持久化：本地 `AgingShelves.json`（`System.Text.Json`）。
- 本次不引入任何新技术、新依赖，仅修改 ViewModel 内一个静态生成方法及其注释。

## 实现方案
单点修改：把 `ViewModel/MainViewModel.cs` 中的 `BuildMeshId` 由「六段重复拼接」改为「直接返回老化架号字符串」。

当前实现（第 768-774 行）：
```csharp
/// <summary>
/// 按老化架号生成 Mesh ID，形如 01:01:01:01:01:01（每段两位、共六段）。
/// </summary>
private static string BuildMeshId(int shelfNumber)
{
    return string.Join(":", Enumerable.Repeat(shelfNumber.ToString("D2"), 6));
}
```

目标实现（保持 `static string BuildMeshId(int)` 签名，调用点零改动）：
```csharp
/// <summary>
/// 按老化架号生成 Mesh ID：直接使用原始老化架号，如 10 → "10"（不再补零、不再重复拼接）。
/// </summary>
private static string BuildMeshId(int shelfNumber)
{
    return shelfNumber.ToString();
}
```

关键决策与权衡：
- **保持方法签名不变**：调用点是 `int.TryParse(..., out int number)` 后的 `BuildMeshId(number)`，签名不变即可做到「生成逻辑」与「调用/持久化策略」解耦，改动面最小。
- **不改变调用点的覆盖策略**：`SyncAgingShelvesCore` 中两处调用均带「Mesh_ID 为空才生成」的守卫（新增项第 922-925 行、已存在项第 945-949 行），符合「用户资产不覆盖」的既有约定，用户已确认旧值不动，因此不新增加载时归一化。
- **不做历史数据迁移**：`AgingShelves.json` 中已存在的 `10:10:10:10:10:10` 由用户在界面自行修正，避免静默改写用户数据。
- **零性能影响**：由字符串拼接 + LINQ `Enumerable.Repeat` 简化为单次 `ToString()`，仅发生在老化架同步路径上，复杂度与分配均降低。

## 执行要点（防回归）
- `System.Linq` 在本文件其它位置仍在使用（`AgingShelves.Where(...)`、`FirstOrDefault` 等），移除 `Enumerable.Repeat` 后**不要**删除 `using System.Linq`。
- `BuildMeshId` 只被 `SyncAgingShelvesCore` 的两处调用，不存在其它生成入口，改完无需同步其它文件。
- 注释与文档一致性：`ViewModel/MainViewModel.cs` 第 768-769 行 XML 注释必须同步更新；`CLAUDE.md` 第 99-100 行只写「通过 BuildMeshId 构建 Mesh_ID」、未写死格式，`docs/LightGateway-改造计划.md` 未描述格式，两者均可不改（如需严谨可顺带把 `CLAUDE.md` 的描述补一句「即老化架号本身」）。
- 影响面控制：本改动只影响「Mesh_ID 为空时自动生成」的新值，不影响本地 JSON 读写、接口调用、点位绑定（绑定用的是服务端雪花 `RemoteId`，与 Mesh ID 无关）。
