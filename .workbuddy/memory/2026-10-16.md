## 新增「复制待写入数据」按钮（配置界面）

- 需求：在配置界面（「设备读取结果」Tab）增加一键复制当前即将写入数据的按钮，复制内容必须与待写入数据完全一致。
- 实现方式（关键设计）：把写入载荷构建抽成单一入口 `MainViewModel.BuildPendingWriteJson(out snapshot)`，
  `WriteVerifyAndBindAsync()` 与新按钮的 `CopyPendingWriteData()` 共用，保证复制内容与实际发送的
  ChangeConfig JSON 字节级一致。删除了随之失去调用方的 `GetSnapshotValue()`。
- `BuildPendingWriteJson` 内强制 `ReadUDPPort = "1"`（原写入流程第一行即此设置，已移入），
  否则「读回 8080 → 复制显示 8080 → 实际写入 1」不一致。注意：本地函数不能捕获 out 参数，
  快照需先落到普通局部变量（`wrote`）再读取。
- 复制按钮不要求串口打开、始终可用；复制不写 `WroteSnapshot`（避免污染读取弹窗的一致性结论）；
  配置不完整时仍允许复制，但弹 Warning 提示直接写入会被校验拒绝。
- XAML：按钮放在「写入」旁（SecondaryButton 样式），case `"复制待写入数据"` 加入 `CmdCmdClickAction`。
- 已更新 CLAUDE.md（命令清单 + "Copy Pending Write Payload" 小节，强调共用入口、不要单独拼 JSON）。
- `dotnet build` 通过：0 错误，新增代码 0 警告。

## 「复制待写入数据」格式转换（仅复制按钮）

- 需求：复制按钮输出的格式改为 `{"Seq":<unix秒>,"Data":{"BasicConfig":{...},"ExternalDevices":[...]}}`，
  **仅限复制按钮**；设备写入仍是 `{"Cmd":"ChangeConfig","Value":{...},"ExternalDevices":[...]}`，两条路径格式不同。
- 实现：把取值逻辑拆成共用部件 `CaptureWriteSnapshot()` / `BuildBaseConfigFromSnapshot()` /
  `BuildExternalDevicesPayload()`，写入走 `BuildPendingWriteJson()`、复制走 `BuildCopyPayloadJson()`，
  只各自负责外层信封，取值永远一致。
- `Seq = DateTimeOffset.UtcNow.ToUnixTimeSeconds()`；`BasicConfig` 比写入的 `Value` 多一个
  `IsMqttLog`（上位机无此设置项，固定输出 `"1"`，已向用户说明该假设），字段顺序 = 写入字段顺序
  且在 `SSID` 后插入 `IsMqttLog`。
- 已用临时控制台程序实证验证：写入路径输出与改动前逐字节一致；复制路径输出符合目标格式
  （含 ExternalDevices 空数组与有数据两种场景）。注意：匿名类型中 `object` 类型成员按运行时类型
  序列化，输出不受影响；匿名对象混合简写属性与 `IsMqttLog = "1"` 赋值合法，成员顺序=书写顺序。
- CLAUDE.md "Copy Pending Write Payload" 小节已同步更新（强调两条路径格式不同、不要互相"统一"）。
